# 獎勵設計：量級理由與防 reward hacking 分析

實作：`src/wordle_rl/rewards.py`（EpisodeStats 的純函數，`tests/test_rewards.py`
把以下每一條論證寫成可執行斷言）。GRPO 每條軌跡一個 advantage → 各項相加成
**單一 episode 純量**是正確形態；shaping 不逐回合折現。

## SHAPED preset（預設）

| 項目 | 值 | 上界 | 理由 |
|---|---|---|---|
| 獲勝 | +10 + 1×(6−turns_used) | +15 | 主目標必須支配一切；快勝加成**嚴格遞減**，堵「拖時間刷 shaping」 |
| 新綠位（首次發現，含 Y→G 升級） | +0.2 | +1.0（≤5 位） | 位置資訊是 Wordle 的核心進展訊號 |
| 新存在單位（min_count 增量） | +0.1 | +0.5（≤5 單位） | 黃字回饋也是進展；量級為綠位一半 |
| 非法詞 / 格式錯 | −2 / 回合 | −12 | 必須大於單回合可得的最大 shaping（非勝回合 ≤ +1.3），否則「亂猜換資訊」可套利 |
| 違反已知限制 | −1 / 回合 | — | **故意輕罰**：用已排除字母探測是合法策略（人類高手也這樣打），只施加成本不禁止 |
| 重複同一猜測 | −2 / 次 | — | 重複零資訊且必虧——防「安全水詞」hacking 的下限保證 |

### 量級論證（tests/test_rewards.py 逐條斷言）
1. **shaping 總上界 1.5 << 最差獲勝 10**：「整局刷 shaping 不求勝」最多拿 +1.3
   （5 綠不勝不可能，取 4 綠 + 5 存在），與最差獲勝差距 ≥ 8.5 → 求勝永遠支配。
2. **拖延無利可圖**：shaping 只獎首次發現（與回合數無關），回合加成嚴格遞減
   → 同資訊量下早勝 > 晚勝。
3. **重複懲罰 −2 > 單回合最大 shaping +0.7**（實務值）→ 重複必虧。
4. 首猜直接命中綠位同時計 +0.2（位置）與 +0.1（存在）——兩者都是新資訊，
   上界不變（全綠首猜 = 1.5，也同時是獲勝回合）。

### 已知的殘餘 hacking 面與監控
- **「探測詞」策略**：模型可能故意猜含已排除字母的高頻詞收集資訊（−1 換 ≤+0.7）。
  這是**設計容許**的（淨值為負、人類策略合法），metrics.jsonl 的違限率會顯示趨勢。
- **早期全敗零梯度組**：BINARY 下常見（全 0 組 advantage 全 0）；SHAPED 的 shaping
  差異天然製造組內變異。監控指標：`reward/zero_variance_group_frac`。
  逃生口：加大 num_generations、`scale_rewards="none"`（Dr.GRPO 均值口徑）。
- **樣本才是真相**：每 50 步 3 局 transcript 落 `samples/`，人工抽查是例行公事
  （經典症狀：固定開局詞後永遠同一序列、違限率不降反升、平均回合數貼上限）。

## BINARY preset（A/B 對照）

勝 1.0 / 敗 0.0。HF 官方 TRL openenv Wordle 範例的結論是**純輸贏獎勵優於 shaped**
（shaped 可能誘導「收集資訊但不收斂」的局部最優）。本專案預設 SHAPED 先跑
（理由：1.5B 模型早期勝率趨近 0，BINARY 會大面積零梯度），行有餘力第二晚
`--reward binary` 對照，兩者同表寫進最終報告。

## 煙霧環境（number_guess）

勝 +5 + 0.5×(7−turns)、格式錯 −2、重複 −2。回饋本身已密集（每回合都有方向資訊），
不需要資訊 shaping——煙霧測試的目的只是驗證管線會學，不是雕獎勵。
